# portscanner

一个用 Python 写的端口扫描器（学习项目）。

## 环境要求

- **Python 3**（开发环境：Python 3.14.4 / WSL Ubuntu）
- **无需安装任何第三方库** —— 只用标准库 `socket` / `sys`
- 跨平台：Linux / macOS / Windows 均可

## 用法

    # Linux / macOS 
    python3 scan.py <目标IP> <起始端口> <结束端口>

    # Windows（通常只有 python 这个命令）
    python scan.py <目标IP> <起始端口> <结束端口>

例子：

    # 扫描 1-1024
    python3 scan.py 192.168.75.128 1 1024

    # 只扫一个端口（起始和结束填同一个数）
    python3 scan.py 192.168.75.128 80 80

输出：

    22 开放
    80 开放

### 参数说明

- 三个参数之间**用空格分隔**
- 只扫单个端口时，**起始和结束填同一个数**
- ⚠️ 参数不足 / 端口不是数字时，会给出提示并退出

## 原理

对每个端口尝试建立 TCP 连接（下表为 Linux / WSL 的返回码）：

- 返回 0    → 端口开放
- 返回 111  → 端口关闭（对方回 RST）
- 返回 110  → 超时（被防火墙过滤）
- 返回 113  → 主机不可达

> ⚠️ **Windows 的返回码不同**（`10061` / `10035` / `10065`），详见下方「已知问题」。

## 已知问题

### 1. Windows 下超时机制失效

在 Windows 上，一旦设置了 `s.settimeout()`，
`connect_ex()` 对**关闭的端口**会**一直等到超时**才返回，
而不是立刻返回"连接被拒绝"。

**实测对比**（同一目标、同一端口）：

| 环境 | 返回码 | 含义 | 耗时 |
| --- | --- | --- | --- |
| Linux / WSL | `111` | ECONNREFUSED（确定关闭） | 立刻 |
| Windows（**不设** timeout） | `10061` | WSAECONNREFUSED（确定关闭） | 立刻 |
| Windows（**设了** timeout） | `10035` | WSAEWOULDBLOCK（**还没完成**） | ⚠️ 等满超时 |

**原因**：`settimeout()` 会把 socket 变成非阻塞模式，
而非阻塞 `connect` 立刻返回"还没完成"；
Windows 上没有把该 socket 报告为可写，导致一直等到超时。

**影响**：在 Windows 上扫描时，每个关闭的端口都要等满 timeout，速度大幅下降。

**计划**：改用多线程（每个线程阻塞等待，不设 timeout）+ 显式区分端口状态。

### 2. 端口状态区分不够细

目前只区分「开放」和「非开放」，实际上：

- `111` / `10061` → **确定关闭**（收到 RST）
- `110` / `10035` → ⚠️ **超时** —— 可能是关闭，也可能是**被防火墙过滤**

更专业的做法是分开报告「关闭」和「过滤」（nmap 就是这么做的）。
